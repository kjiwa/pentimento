# pentimento

Status, intent, and lineage over agent plan files.

![demo](demo/pentimento.gif)

Claude Code and Cursor (and other harnesses) accumulate plan files with no
status, no starring, and no record of which plan supersedes which. pentimento
reads a directory of plan markdown files, derives a small frontmatter block
for each one (`status`, `intent`, `tags`, `parent`, `project`, `created`), and
gives you a CLI to list, filter, and render them as a lineage tree.

## Install

```sh
pip install -e .
# or straight from the git URL:
pip install git+https://github.com/kjiwa/pentimento.git
```

## Quick start

Point `AGENT_PLANS_DIR` at your plans directory (it defaults to
`~/.claude/plans`), then:

```sh
pentimento backfill      # derive status/intent/created/parent/project once
pentimento list          # see the corpus
pentimento set some-plan-id --intent active
pentimento list --starred
```

Sources and their default directories are covered in
[docs/integrations.md](docs/integrations.md); Cursor's caveats are in
[docs/troubleshooting.md](docs/troubleshooting.md).

## Commands

```sh
pentimento list [--status STATUS] [--intent INTENT] [--project PROJECT] [--source claude|cursor] [--starred] [--tag TAG]... [--sort modified|created|id|status|title] [--order asc|desc] [--format table|json|tsv] [--color auto|always|never] [--ascii]
pentimento tree [--status STATUS] [--intent INTENT] [--project PROJECT] [--source claude|cursor] [--starred] [--tag TAG]... [--sort modified|created|id|status|title] [--order asc|desc] [--format table|json|tsv] [--color auto|always|never] [--ascii]
pentimento show <id> [--format table|json|tsv] [--color auto|always|never] [--ascii]
pentimento set <id> [--status STATUS] [--intent INTENT] [--parent ID] [--clear-parent] [--project PROJECT] [--add-tag TAG]... [--remove-tag TAG]... [--clear-tags]
pentimento backfill [--dry-run] [--quiet] [--rederive] [--recreate]
pentimento index
pentimento check [--format table|json|tsv] [--color auto|always|never] [--ascii]
pentimento --version
```

`--format` defaults to `table` (human-readable); `json` and `tsv` are for
scripting. `--color` defaults to `auto` -- ANSI colour on a tty, off when
piped, `NO_COLOR` is set, or `TERM=dumb`. `--ascii` forces `+- `/`` `- ``/`|  `
box-drawing instead of the Unicode `├─ `/`└─ `/`│  ` `tree` uses by default
whenever the output stream's encoding is UTF-8. `--sort` defaults to
`modified`; every sort key is ascending by default, so the row nearest the
prompt is the most recent one, as with `ls -ltr` and `git log --reverse`.
`--order desc` flips it for any key.

The samples below are regenerated by `sh demo/capture.sh`.

### list

`list` is one line per plan, with both `PLAN` (the id every other command
takes -- `show`, `set`, `check`'s `plan_id`) and `TITLE` (the H1). `PROJECT`
and `SOURCE` only appear when the corpus has more than one distinct value;
`TAGS` only appears when at least one plan has tags; `CREATED` only appears
when at least one plan has the frontmatter field. Columns are content-width
-- `pentimento/table.py` never stretches a column to fill the terminal, so
surplus width goes unused at the right edge. Every command guarantees its
output fits `style.terminal_width()`: when a line would overflow, `TITLE`
and `PLAN` shrink toward their floors first, then columns drop in order
(`CREATED`, `TAGS`, `SOURCE`, `PROJECT`, `PLAN`, `INTENT`, `STATUS`) --
`TITLE` is never dropped, and `AGE` stays flush right.

`backfill` fills in missing fields without touching what's already set.
`--rederive` instead recomputes `status`, `parent`, and `project` from
scratch and overwrites them -- `intent` (operator-owned) and `created`
(immutable) are never touched; a re-derivation that finds no parent removes
an existing `parent` key. `--recreate` is the one way to change `created`: it
recomputes it from local time.

### check

`check` validates the corpus -- dangling parents, self-parents,
cross-project parents, cycles, duplicate ids across sources,
off-vocabulary `status`/`intent` values, missing titles, malformed tags, a
missing `## Progress` heading, and an underived `project` -- and exits 1
on any finding. The table output's `CODE` column is the same code
`docs/troubleshooting.md` and `--format json|tsv` use, so a finding is
always one lookup away from its fix. See
[docs/troubleshooting.md](docs/troubleshooting.md) for what each finding code
means and how to fix it.

```
CODE             PLAN                   MESSAGE
dangling-parent  billing-invoice-retry  parent 'no-such-plan' does not resolve to a plan
8 plans checked, 1 finding
```

## Frontmatter

```yaml
---
pentimento:
  status: not-started | partial | complete | superseded | unknown
  intent: active | queued | someday | abandoned | unset
  tags: [auth, security]        # omitted if untagged
  parent: some-other-plan-id    # omitted for roots
  project: platform             # omitted if undetermined
  created: 2026-09-08
---
```

The vocabulary lives in one place:
[pentimento/vocabulary.py](pentimento/vocabulary.py).

`status` is derived automatically -- every `backfill` run recomputes it from
the `## Progress` checkboxes, so it never goes stale even without
`--rederive`. It's also correctable: `set --status` is the one way to set
`superseded` (an operator-only, never-derived value) or to override a
derivation stuck at `unknown`. `intent` is only ever set by the operator, so
a half-implemented plan can still be marked abandoned. `tags`
is likewise operator-owned and never derived or touched by `backfill` --
set it with `set --add-tag`/`--remove-tag`/`--clear-tags`, and filter on it
with `list`/`tree --tag`, which is an AND filter when repeated. `parent`
and `project` are usually derived by `backfill`, but `set --parent` and
`set --project` can author them directly -- `set --parent` refuses a value
that resolves to no plan in the corpus.
`created` is a local-date (`YYYY-MM-DD`), derived once and then immutable
except through `backfill --recreate`. `modified` is not stored in
frontmatter; it comes from a plan's session log last-activity timestamp,
falling back to the file's mtime when there is no session record.
`backfill` preserves mtime — deriving frontmatter is not an edit.

Lineage and source discovery are covered in full in
[docs/integrations.md](docs/integrations.md) and
[docs/troubleshooting.md](docs/troubleshooting.md); in short, `parent` comes
from a plan's session log or body referencing an earlier, same-project,
same-source plan by `<id>.md`, and Cursor plans get body-only lineage and no
`project` at all.

Zero runtime dependencies: this is stdlib-only Python 3, no PyYAML, so it
ships as a plain CLI.
